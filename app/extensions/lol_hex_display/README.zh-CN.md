# LOL Hex Display

LOL Hex Display 是一个用于《英雄联盟》的海克斯强化识别与战绩展示扩展，既可以独立运行，也可以由 B 站直播弹幕助手主程序统一管理。

## 页面入口

| 页面 | 独立运行地址 | 主程序托管地址 |
|---|---|---|
| 管理页 | `http://127.0.0.1:8767/` | `/extensions/lol-hex/` |
| 海克斯展示页 | `http://127.0.0.1:8767/display` | `/extensions/lol-hex/display` |
| 战绩条 | `http://127.0.0.1:8767/bar` | `/extensions/lol-hex/bar` |

默认服务端口为 `8767`。

## 管理页

管理页提供扩展运行状态和本地数据管理功能：

- **客户端与账号状态：**显示是否识别到可用的英雄联盟客户端、LCU 是否可用，以及能够获取到的账号信息。
- **截图采集：**游戏中按 **F1** 冻结画面并框选区域；再次按 **F1** 或按 **Esc** 取消框选。
- **截图与数据管理：**查看已采集的截图和生成的卡片、打开截图目录，并按需清理卡片或截图。
- **海克斯索引维护：**检查并更新海克斯索引；需要重新构建时可以重置索引。

OCR 无法可靠识别海克斯名称时，会保留并展示截图供人工查看，不会猜测或生成不确定的名称。截图文件删除失败时，程序会在内存中保留已处理标记，避免同一截图被反复识别并重新生成卡片。

## 展示逻辑

- **海克斯展示页：**展示识别到的海克斯信息；无法可靠匹配名称时，改为展示截图，供人工确认。
- **战绩条：**展示扩展生成的对局相关卡片。
- **综合展示：**主程序的综合展示布局编辑器可以分别添加海克斯展示页和战绩条组件，并由主程序布局控制组件的位置与缩放。
- **客户端状态：**扩展会定期检查英雄联盟客户端连接和账号身份，并缓存账号信息供页面展示及相关处理使用。

## 主程序托管模式

- 在主程序的接入中心启动或停止 Hex 扩展。
- Hex 负责英雄联盟客户端识别、截图采集、OCR、海克斯数据及自身展示页面。
- Windows 下主程序启动 Hex 时会请求管理员权限。全局 **F1** 截图热键需要管理员权限，请允许 UAC 提权提示。
- OBS WebSocket 连接、重连和浏览器源刷新统一由主程序负责。托管模式下 Hex 不会另行创建 OBS WebSocket 连接。
- 主程序综合展示布局编辑器将海克斯展示页和战绩条作为两个独立组件提供。

## 配置

My-LiveHub 托管模式使用：

- 默认配置模板：`config/default/lol_hex_display.json`
- 本机配置文件：`config/local/lol_hex_display.json`
- 在 My-LiveHub 的「扩展管理」页面手动启动或停止；不会随主程序启动而自动运行。
- 开发环境优先使用扩展目录下的 `.venv\\Scripts\\python.exe`；没有该虚拟环境时才使用 `python` 命令，也可通过 `MY_LIVEHUB_PYTHON` 指定解释器。
- 首次源码运行可在此目录执行：`py -3.10 -m venv .venv`，然后执行 `.venv\\Scripts\\python.exe -m pip install -r requirements.txt`。
- 已打包时优先启动 `dist/lol_hex_display/lol_hex_display.exe`。

本机 JSON 配置包含服务监听地址与端口、截图目录、扫描间隔、资源/版本/游戏流程检查间隔，以及英雄联盟客户端安装目录等机器相关设置。不同机器的路径应写入本机配置，不要写入受版本控制的默认模板。

升级时，如果本机 JSON 不存在且旧版 `extensions/lol_hex_display/config.txt` 存在，程序会将可识别的旧配置迁移到本机 JSON。若本机 JSON 已存在，则始终以本机 JSON 为准。

独立运行时可以通过 `--config <path>` 指定配置文件；未指定时，程序会尝试读取应用目录旁的 `config.json`。如果该文件也不存在，则使用内置默认值。

## 本地运行数据

扩展会按需创建以下目录或文件：

- `data/`：OCR/海克斯元数据缓存和运行状态。
- `screenshots/inbox/`（默认）：采集的截图及源文件；运行时实际使用配置中指定的截图目录。
- `logs/`：应用日志和定期线程诊断信息。
- `lol_hex_display.pid`：供主程序管理器识别当前进程的 PID 文件。

这些均为本机运行数据，已由仓库 `.gitignore` 忽略。运行 Python 源码时还可能生成 `__pycache__/`，同样会被忽略。

扩展自身的 `build.bat` 会生成目录式 EXE 发布包，输出到 `dist/lol_hex_display/`。打包前先安装 `requirements.txt` 中的依赖。发布 My-LiveHub 时，需要将该目录随主程序放到 `extensions/lol_hex_display/dist/lol_hex_display/`。本机的 `data/`、`screenshots/` 和 `logs/` 不会随扩展 EXE 打包。
