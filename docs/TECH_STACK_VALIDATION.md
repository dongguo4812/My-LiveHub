# My-LiveHub 桌面技术栈验证计划

> 文档版本：V0.1
> 状态：待验证；候选技术路线，不代表最终定稿
> 更新日期：2026-11-08

## 1. 验证目标

在建立正式业务项目骨架之前，以最小验证程序确认桌面宿主、Web 前端、Go 核心和 OBS 浏览器展示入口能够按预期协作。

本阶段只验证技术可行性，不迁移旧项目业务功能，不提前设计完整扩展 SDK，也不将候选技术栈视为不可更改的最终决定。

## 2. 候选技术路线

| 层次 | 候选方案 | 验证重点 |
|---|---|---|
| Windows 桌面宿主 | Wails v3 | 窗口、托盘、生命周期、WebView2 集成 |
| 核心服务 | Go | 生命周期、HTTP 服务、事件推送 |
| 客户端前端 | Vue 3 + TypeScript + Vite | 与 Wails 的集成和构建 |
| 客户端 UI 组件库 | Element Plus | 常用复杂控件、主题和布局适配 |
| OBS 展示前端 | Vue 3 + 自定义 CSS | 独立访问、透明背景、布局自由度 |
| OBS 展示入口 | Go 本机 HTTP 服务 | 与桌面窗口解耦、多个独立页面入口 |

管理界面组件库用于桌面客户端的操作界面，不意味着产品是网页管理后台。OBS 展示页面不强制使用 Element Plus。

## 3. 最小验证范围

### 3.1 桌面窗口与生命周期

- 启动 Windows 桌面程序并显示 Vue 客户端界面。
- 创建、显示、隐藏和关闭第二个窗口。
- 验证系统托盘及从托盘恢复主窗口。
- 验证主窗口关闭、应用退出和后台服务停止之间的行为。
- 验证重复启动、重复关闭等边界情况。

### 3.2 Go 与前端通信

- 前端调用 Go 暴露的简单方法并接收结果。
- Go 主动向前端推送状态变化。
- 验证高频连续推送时 UI 不明显卡顿。
- 验证前端窗口关闭或重新创建后，订阅关系能够正确释放和恢复。
- 确认业务逻辑不依赖某个窗口长期存在。

### 3.3 OBS 独立展示入口

- Go 启动本机 HTTP 服务。
- 使用独立 URL 打开展示页面，不依赖 Wails 主窗口。
- 在 OBS 浏览器源中加载该 URL。
- 验证透明背景、页面刷新和多布局独立 URL。
- 关闭桌面主窗口但保持应用服务运行时，确认展示页面行为符合设计；应用完全退出后，展示服务应正常停止。

### 3.4 实时事件展示

- Go 生成带递增序号的模拟事件。
- 通过拟采用的实时通信方式推送到客户端和 OBS 展示页面。
- 验证两个界面均能接收同一事件，且不重复建立平台连接。
- 测试持续推送、突发推送、前端刷新和短暂断连后的恢复行为。
- 记录事件产生至界面显示的延迟和资源占用。

### 3.5 稳定性与资源

- 检查空载和持续事件推送时的 CPU、内存占用。
- 验证 WebView2 页面崩溃或窗口关闭后的恢复能力。
- 验证 HTTP 服务、事件推送和窗口生命周期互不意外阻塞。
- 验证应用退出时 goroutine、监听端口、窗口和子进程正确释放。
- 进行至少一次连续运行测试；正式验收时再确定更长时间和量化阈值。

## 4. 验证原则

1. 验证程序应尽量小，只包含窗口、通信、模拟事件和展示页面。
2. 不接入真实直播平台，不连接 OBS WebSocket，不迁移音乐、视频、TTS 或 Live2D。
3. 不因验证方便而把 OBS 展示页面绑定到桌面窗口生命周期。
4. 记录实际使用的 Go、Wails、WebView2、Node.js 和前端依赖版本。
5. 记录构建、启动、关闭、刷新和异常恢复步骤，确保结果可复现。
6. 遇到框架限制时，先评估是否有可靠解决方式，再决定是否调整技术路线。

## 5. 通过标准

- Windows 桌面程序能够稳定启动并运行。
- 主窗口和辅助窗口可以独立管理。
- Go 与前端双向通信及 Go 主动事件推送正常。
- OBS 浏览器能够通过独立本机 URL 访问展示页面。
- 管理界面和 OBS 展示页面可以独立刷新，不造成核心状态异常。
- 页面异常、窗口关闭和应用退出时资源能够正确释放或恢复。
- 运行资源和事件延迟达到后续基准测试设定的目标。

具体 CPU、内存、延迟和持续运行阈值在确定测试机器及实现后补充，不在缺乏实测数据时预设结论。

## 6. 验证完成后的决策

- 全部关键项目通过：将候选技术路线升级为正式选型。
- 个别项目存在可解决问题：记录解决方案和维护成本后复测。
- 出现影响核心目标的框架限制：重新比较桌面宿主方案，不因已投入验证而强行采用。

技术路线通过验证后，下一阶段进入 Go 核心与独立扩展进程之间的通信协议设计，包括传输方式、消息信封、请求响应、事件订阅、权限、超时、心跳和进程退出约定。
